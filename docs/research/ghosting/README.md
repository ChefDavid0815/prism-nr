# 运动鬼影：真实录像上的离线研究

## 方法

1. Prism Core 的录制功能（`prism-core.ini` 里写 `Record=90`）连续录下游戏的超分输出、运动矢量和深度。第一段数据：CONTROL Resonant，角色在开场走廊里往前走，2560×1566，取有结构的前 40 帧，裁出人物和门框所在的 1280×768。
2. `tools/ghost/prep.cjs` 按 Core 的算法生成网络输入：代理画面（16×16 分块对数亮度曝光，缓动 0.05，高光压缩，sRGB）、输出分辨率下的运动矢量和深度。另外生成"每 N 帧"的网络序列，分别给网络近似运动（发射帧运动 × 间隔帧数，1.1 的做法）和精确运动（逐帧沿运动矢量回溯的真实位移）。
3. `tests/nr_bench seq` 用真实网络（310.9.16.0）跑这些序列，每帧都跑的结果作为参考答案。
4. `tools/ghost/eval.cjs` 逐像素复现 Core 的着色器（携带、落地、取样、填充），把每种方案显示出来的改动和参考答案比较：全图误差、运动区域（位移大于 1.5 像素）、深度边缘带，以及闪烁（相邻帧改动的变化量和参考的变化量之差）。单位都是档（log2）。

数据在 `F:\PrismNR-research`。

## 结论

| 方案 | 全图 | 运动区域 | 深度边缘 | 闪烁 |
|---|---:|---:|---:|---:|
| 不开神经渲染（参照：改动本身的大小） | 0.130 | 0.202 | 0.188 | 0.025 |
| 1.2 默认：每 4 帧，逐帧链式携带，近似运动 | 0.102 | 0.157 | 0.173 | 0.058 |
| 每 2 帧（同帧落地加发射），链式携带，近似运动 | 0.080 | 0.123 | 0.144 | 0.060 |
| + 直接从落地答案取样 + 精确运动 | 0.074 | 0.112 | 0.138 | 0.056 |
| + 同深度邻域填充 | 0.060 | 0.090 | 0.143 | 0.046 |
| **+ 时间平滑 α = 0.7（新默认）** | **0.061** | **0.091** | **0.141** | **0.038** |

1. **误差主要由显示的改动有多旧决定**，不是重投影不准：落地晚一帧，误差就涨约 16%；运动矢量膨胀、坐标场直采单独用几乎没有收益。所以缩短节奏是最大的杠杆，新模型开销减半后每 2 帧负担得起。
2. **同帧落地加发射**：把落地的网络答案单独烘焙出来，落地那一帧就能立刻发射下一次，否则"每 2 帧"实际会变成每 3 帧。
3. **精确运动让网络自己的输出更准**：在发射帧上，网络输出和参考的误差从 0.033 降到 0.015。
4. **新露出的区域是边缘误差的主要来源**：发射时被前景挡住的背景，网络答案里没有它。用同深度邻域的改动填充后，全图误差再降约 20%，闪烁也随之下降。
5. **一致性衰减（底下画面变化大就淡出改动）有害**：会把正确的改动也淡掉，误差反而上升 16%。
6. **α = 0.7 的时间平滑**几乎不增加误差（+1%），闪烁降低 17%。

合计：运动区域的误差比 1.2 实验分支的默认（poll 落地、每 4 帧）低 42%，闪烁低 34%。

和实际发布的 1.1.1 比（每 4 帧、等 fence 下一帧落地、链式携带、近似运动）：全图误差 0.085 → 0.061（−28%），运动区域 0.129 → 0.091（−29%），闪烁 0.062 → 0.038（−38%）。对外宣传用这一组。

## 限制和下一步

- 只有一段 40 帧的 CONTROL 走路录像；赛车游戏（地平线 6）的高速运动、反射、树影要用新录像复测。
- 落地年龄按 poll 的典型值 2 帧模拟；落地年龄 1（网络在下一帧录制前就算完）时误差会更低。
- 边缘带误差下降有限，可以试更精细的填充（按深度梯度方向取样）。
