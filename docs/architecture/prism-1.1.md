# Prism 1.1 架构：Prism Core

2026-10-21 · 草案。技术依据见 [DLSS 5 神经渲染技术研究报告](../research/dlss5-neural-rendering.md)。

## 目标

让神经渲染在 RTX 5050 / 5060 / 5070 和笔记本上也能流畅地开，而且画面损失尽可能小。

量化目标（以 RTX 5060、2560×1440 输出、新模型为基准，均为设计目标，需实测验证）：

| 指标 | 社区现状 | 1.1 目标 |
|---|---|---|
| NR 每帧平均成本（含自身合成） | 整屏 ≈ 8.5 ms（估算）；Skynizz x8 平均约 0.9 ms 但不均匀（4070 实测） | ≤ 3 ms（含焦点窗口），流畅档 ≤ 1.8 ms |
| 帧时间摆动（p99） | Skynizz x8：1.8 ms；隔帧方案 5 ms 级 | ≤ 0.5 ms（恒定成本） |
| 效果保留（对比整屏每帧 NR） | x8 平移 89% | ≥ 92% |
| 人脸区域细节 | 50% 分辨率时永久损失 | 原生分辨率 |
| 用户需要调的参数 | 几十个 | 只选目标帧率 |

## 总体结构

**Prism Core 是独立运行时，不依赖 ReShade，也不依赖 OptiScaler。**

理由：游戏调用 DLSS 超分时，`NVSDK_NGX_D3D12_EvaluateFeature` 的参数块里已经有神经渲染需要的全部输入——颜色、输出、运动矢量、深度、抖动、重置标志、渲染与输出分辨率。直接拦截 NGX，就拿到了最干净的输入，前置超分（在渲染分辨率上跑）和后置（在输出上跑）都是自然的插入点。ReShade 在这里只是一层多余的注入和资源追踪，还带来与其他 ReShade 预设的冲突；OptiScaler 是 GPL，也背着大量与 NR 无关的功能。

- **加载**：一个代理 DLL（`version.dll` / `winmm.dll` / `dxgi.dll` 中游戏没占用的那个，由 Prism 安装时自动挑），转发系统函数，并加载 `prism_nvngx.dll`。名字里带 `nvngx.dll`，是因为 NGX 只允许路径含这个字样的模块创建 feature（neural-upstream 的发现）。
- **拦截**：MinHook 挂住所有导出 NGX 求值/创建/释放函数的模块（驱动的 `_nvngx.dll` 和任何代理），用线程本地的调用链去重（RenoDX 的 `EvaluateChain` 思路），一次真实求值只注入一次。
- **计算**：自己的 D3D12 计算管线，HLSL 由系统自带的 `d3dcompiler_47.dll` 在运行时编译（SM 5.1），录制进游戏的命令列表或我们自己的计算队列。
- **控制**：不做游戏内菜单。Prism 应用通过命名管道实时调参、实时看遥测（每阶段毫秒、档位、焦点窗口位置），游戏里只保留 F6 / F7 热键。
- **Prism FX**：现有 6 个 ReShade 着色器改写成 Core 内部的计算着色器，在编辑域里和 NR 一起合成，不再需要 ReShade。
- **没有 DLSS 的游戏**：保留 0.1 的 ReShade + Feeder 路线作为后备。

## 核心技术

### ⚠ 真实网络的裁决（2026-10-21，必读）

下面 NETS 一节的离线结论建立在"网络在低分辨率下的回答 ≈ 全分辨率回答的缩小版"这个假设上。用 Prism 测试台在 RTX 5090 上**直接跑真实网络**之后，这个假设被推翻了：

| 对比真实全分辨率网络输出（同一段合成镜头，静止段） | 细节相关度 | 误差（档） |
|---|---:|---:|
| 固定网格 50%（RenoDX 做法） | 0.49 | 0.161 |
| NETS 50%（抖动 + 累积） | 0.37 | 0.162 |
| 固定网格 35% | 0.23 | 0.186 |

1. 网络在低分辨率下合成的是**不同的细节**，不是缩小的细节；抖动到不同位置，每次合成的细节互相不一致，累积只会更糊。**NETS 按原设计不成立，暂停。**
2. 网络对一个原生分辨率裁剪块的回答，细节与整帧高度一致（96 px 重叠时相关度 0.88），差别在低频整体调色（上下文少了）。
3. **双频合成**被证实有效：块的高频 + 整帧 50% 的低频，误差 0.122、细节 0.88，好于两者单独。块与块的接缝还在（0.20，整帧本身在该处 0.07），需要在重叠区羽化混合。
4. 网络自身在静止时非常稳定（帧间变化 0.016 档），全分辨率答案很适合在时间上复用。
5. 每次求值约 1.45 ms 固定开销，所以多槽、分块这类空间技巧的收益被大幅压缩。

**第二轮真实网络实验：时间复用 vs 空间切分**（同一段合成镜头，对比"每帧整帧全分辨率"）

| 方案 | 静止误差 | 静止细节 | 慢移误差 | 快移误差 |
|---|---:|---:|---:|---:|
| **整帧全分辨率隔帧 + 重投影** | **0.034** | **0.93** | **0.047** | **0.045** |
| 半屏轮转（96 px 重叠、羽化） | 0.116 | 0.91 | 0.126 | 0.108 |
| 半屏 + 整帧 50% 低频 | 0.128 | 0.91 | 0.142 | 0.128 |
| 整帧 50%（RenoDX 做法） | 0.161 | 0.49 | 0.166 | 0.157 |

晚一帧的全分辨率答案沿运动矢量重投影，误差只有每帧 50% 的五分之一。空间切分（块、半屏、降分辨率）都更差，因为网络依赖整帧上下文决定整体调色。

**异步重叠：否定**（`nr_bench async`，5090，1440p）。替身负载是纯计算着色器：算力型时一起跑反而多耗 19%，带宽型多耗 40%。网络不是张量瓶颈（neural-upstream 反汇编显示以整数地址运算为主），和游戏抢同一批着色器核心。异步队列只能平滑帧时间，不能凭空省成本。真实光栅帧会有空闲时段，替身负载是最坏情况，但方向明确。

**修订后的方向（以数据为准）**：
1. **质量核心 = 整帧全分辨率答案的时间复用**（编辑缓存、重投影、指纹校验）。隔帧的质量损失极小。
2. **成本 = 隔帧或自适应节奏**。帧时间锯齿是代价，由节奏控制（静止时拉长、运动时缩短）和帧生成配合来处理。
3. **前置超分**（在渲染分辨率上跑）是另一大杠杆，需要接上游戏的 DLSS 超分后实测质量。
4. 角色守护照常叠加。
5. 下一步：Prism Core 进游戏（代理加载 → 拦截 NGX 求值 → 自建 NR feature → 编辑缓存 → 守护 → 写回），在 CONTROL 上实测帧率和画质，对比 RenoDX 与 Skynizz。

### 游戏内实测（2026-10-21，CONTROL Resonant，RTX 5090 Laptop）

Prism Core 已经作为独立运行时跑进游戏：`version.dll` 代理加载 → 拦截 NGX（游戏用的是光线重建 Feature 13）→ 自建参数对象和 NR feature → 自己的 D3D12 计算管线（曝光、编码、网络、守护、合成）。不依赖 ReShade、RenoDX、OptiScaler。

同一静止镜头（序章走廊，输出 2560×1600，渲染 1280×800），游戏内计时：

| 模式 | 渲染帧率 | 相对关闭多耗 | Prism 的 GPU 时间 |
|---|---:|---:|---|
| 关闭 | 52.2 FPS | — | — |
| 每帧跑网络（相当于 RenoDX 单遍） | 32.0 FPS | +12.1 ms | 10.4 ms |
| 同步隔一帧 + 编辑沿运动矢量携带 | 37.5 FPS | +7.4 ms | 跑网络帧 10.4 ms，携带帧 0.13 ms |
| 同步隔三帧 | 38.9 FPS | +6.5 ms | 平均 2.5 ms |
| 异步隔一帧 | 32.4 FPS | +12.0 ms | 与游戏争抢，反而变慢 |
| **异步隔三帧** | **43.0 FPS** | **+4.0 ms** | 图形队列上只剩 0.2 ms |

发现：
1. **帧节奏会把尖峰摊到每一帧**：同步隔帧时帧间隔不是长短交替，而是被统一拉长（约 65–70% 的尖峰进入平均帧时间），所以同步模式隔一帧以上几乎没有收益。
2. **异步队列在网络空闲时间足够时才有效**：隔三帧异步把网络挪到计算队列，与游戏后续帧并行，成本从 12.1 ms 降到 4.0 ms（−67%），帧率比每帧跑高 34%；隔一帧异步时网络几乎持续占用着色器核心，反而更慢。
3. 真实网络离线验证异步隔三帧的画质：误差 0.061–0.086 档、细节 0.70–0.89，误差不到 RenoDX 50% 省性能模式（0.16、细节 0.49）的一半。短板是快速移动的人脸（细节 0.55–0.65），需要运动自适应节奏。

### ② NETS：神经编辑时域超采样（原设计，已被真实网络否决，保留作记录）

**问题**：社区降成本只有两条路。隔帧（成本锯齿，帧生成下卡顿）；或固定降分辨率（每帧都从同一个低分辨率网格放大，丢掉的细节永远回不来）。

**做法**：借用 DLSS 超分本身的思路，但对象换成"网络的编辑"。

1. **每帧都跑网络**，但只在工作分辨率上（例如 50% → 1/4 像素，35% → 1/8 像素）。成本恒定，帧时间没有锯齿；模型的时间历史每帧连续，不会因为跳帧而失效。
2. 每帧缩小时，把采样窗口平移一个**亚像素相位**（Halton 序列，4 或 8 个相位轮转）。等于每帧采到原图不同位置的样本。改动点就是 RenoDX v6 编码着色器里那个面积加权缩小的采样窗口。
3. 喂给网络的运动矢量要加上相位差（`Δφ`），网络的历史才能跟上这个平移。我们自己生成工作分辨率的 MV 纹理（缩小游戏 MV + 叠加 `Δφ`）。
4. 网络输出的编辑 `e = log2(n / p)`，每个样本都知道自己对应全分辨率的哪个位置。
5. 全分辨率**编辑累积缓冲**：上一帧的累积沿 MV 重投影，按深度、颜色指纹校验；再把这一帧的样本按距离加权聚合进来（类似 TAAU / FSR2 的时域上采样）。历史权重有上限，防拖影。
6. 静止画面 4–8 帧内收敛到接近全分辨率的编辑；运动时退回单帧边缘感知放大的质量，而运动本身会掩盖细节。

**和社区比**：成本与 Skynizz x8 的平均成本同级（35% 档约 1/8），但帧时间平坦；画面细节随时间恢复，而不是永久损失。

**风险**：网络可能把抖动当成噪声自己平滑掉，那累积能恢复的细节会少一些，但不会更差。这必须在 RTX 50 上实测（见验证计划）。

#### 离线验证（2026-10-21，`tools/nets-sim`）

用 CONTROL 审讯室同一帧的真实神经渲染结果（RenoDX 强度 1.0、2 遍，对比原画）作为标准答案，合成一段镜头：静止 24 帧、慢速平移 24 帧（0.4 px/帧）、快速平移 24 帧（3 px/帧），另有一个前景人脸层以 2.2 px/帧穿过画面，带自己的深度和运动矢量。每段跳过前 8 帧，只统计稳态。

前提假设：网络在低分辨率下的回答，等于全分辨率回答的盒式滤波。真实网络在低分辨率下可能合成不同的细节，所以这组数字衡量的是**重建算法**能找回多少，不是网络本身。

| 方案 | 网络像素 | 细节相关度 | 平均误差（档） |
|---|---:|---:|---:|
| RenoDX 固定网格 71% | 50% | 0.863 | 0.0600 |
| 理论上限 50%（无穷多相位） | 25% | 0.853 | 0.0586 |
| **NETS 50% + 输出锐化** | **25%** | 0.810 | **0.0612** |
| RenoDX 固定网格 50% | 25% | 0.748 | 0.0765 |
| 理论上限 35% | 12.2% | 0.722 | 0.0746 |
| **NETS 35% + 输出锐化** | **12.2%** | 0.700 | **0.0746** |
| RenoDX 固定网格 35% | 12.2% | 0.581 | 0.0960 |

结论：**误差相同时，NETS 只需要一半的网络像素**；35% 档已经达到理论上限的 88%。理论上限本身由样本的盒式足迹决定，要超过它只能靠原生分辨率的焦点窗口。

迭代中确定的做法（每一条都有数据支持）：

| 改动 | 效果 |
|---|---|
| 历史用 Catmull-Rom 读取（夹在 2×2 双线性范围内防振铃） | 运动人脸细节 0.64 → 0.71；双线性每帧都会把历史模糊一点 |
| 历史权重上限随速度下降 `wmax / (1 + 2·|v|)` | 快速平移 0.75 → 0.80 |
| 新样本增益 3 | 新信息进得更快，全段 +0.005 |
| 锐化只作用在输出上，不写回历史 | 误差 −7% |
| 8 相位 Halton | 4 相位静止段差 0.02；16 相位无收益 |
| ~~低频每帧锚定到当前帧~~ | 写回历史会形成反馈、慢移段误差 0.06 → 0.20，**放弃**；网络改主意的问题改由历史权重上限和指纹校验处理 |

#### GPU 实现（2026-10-21，`native/prism-core`）

着色器在 Intel 核显（Ultra 9 275HX 集成显卡）上用 D3D12 运行，与 CPU 参考逐像素比对，再计时。没有使用 RTX 显卡。

| 版本 | 正确性（对比 CPU 参考） | 1080p | 1440p | 4K |
|---|---|---:|---:|---:|
| 参考版：填充一遍 + 累积一遍，32 位 | 最大误差 2.6×10⁻⁵ 档，0 像素超差 | 7.3 ms | 16.6 ms | 35.0 ms |
| **生产版 `nets_step.hlsl`**：单遍，填充只在无历史像素上按需计算，16 位存储 | 51.8 万像素中 4 个（0.0008%）因半精度落在阈值另一侧，其余一致 | **3.3 ms** | **5.1 ms** | **15.1 ms** |

核显的显存带宽约为 RTX 5060 的 1/4.5、算力约 1/20。按带宽比例保守推算，生产版在 RTX 5060 上 1440p 约 1.1 ms，按算力比例约 0.3 ms，真实值以 M2 实测为准。还没做的优化：改用纹理和硬件双线性采样（Catmull-Rom 可从 16 次读取降到 5 次）、历史与指纹合并成一张纹理。

### ③ 焦点窗口：把原生分辨率留给人脸（壁垒二）

**问题**：所有方案都是整屏一刀切。天空和人脸拿同样的分辨率。

**做法**：

- 第二个 NR 槽，固定尺寸的小窗口（例如 1440p 下 960×540，约占画面 14%），**原生分辨率**，每帧跑。
- 窗口位置跟随显著区域：GPU 在 1/8 分辨率上算块得分（肤色概率 × 中心先验 × 前景深度 × 局部对比），积分图找得分最高的窗口，回读延迟 2–3 帧没关系。窗口用临界阻尼弹簧移动，带滞回，防止抖动；窗口移动量要折算进这个槽的 MV，保持它的时间历史。
- **双频合成**：小窗口里网络看到的上下文少，整体调色可能和全屏不一样（模型里有 attention）。所以只取窗口编辑的高频部分（`e_B − lowpass(e_B)`），低频始终来自全屏 NETS，羽化边界。亮度不会出现接缝。

### ④ 编辑累积与校验（吸收社区成果）

直接借鉴已被验证的做法：log 比值编辑（经得住光照变化）、低频/高频分离、深度 + 颜色指纹校验、无 MV 物体的 soft refresh、光源进入画面时的调色突变平滑。区别在于这些机制在 Prism Core 里服务于 NETS 的时域累积，而不是隔帧复用。

### 真实网络成本（2026-10-21，`native/prism-core/tests/nr_bench.cpp`）

Prism 自己的测试台在游戏之外直接加载签名版 `nvngx_dlssnr.dll`（8 月 28 日版，旧模型），在 RTX 5090 Laptop 上创建 Feature 18 并计时。要点：这个签名运行时**不导出参数分配函数**，测试台自己实现了一个按 MSVC 虚函数表布局的参数对象（17 个槽位，每组重载倒序），运行时直接回调它。

| 分辨率 | 网络耗时 | 每百万像素 |
|---|---:|---:|
| 1280×720 | 3.25 ms | 3.53 ms |
| 1920×1080 | 5.43 ms | 2.62 ms |
| 2560×1440 | 8.32 ms | 2.26 ms |
| 2560×1600 | 9.11 ms | 2.23 ms |
| 3840×2160 | 17.69 ms | 2.13 ms |

**成本不是纯线性**：约 1.45 ms 固定开销 + 每百万像素约 1.96 ms。设计上的含义：
- 降分辨率的收益比按面积算的小：1440p 的 50% 档实际快 2.6 倍，不是 4 倍。
- 焦点窗口作为第二个网络槽，要多付一次固定开销。更划算的做法可能是把焦点窗口拼进 NETS 的同一张输入里（一次求值），待验证。
- 应用层求解器的成本模型要改成"固定 + 线性"两项。

### ⑤ 角色守护（壁垒三）

已在真实画面上验证（`tools/nets-sim --guard`，着色器 `native/prism-core/shaders/guard.hlsl`）：

| 区域 | RenoDX 颜色偏移（CbCr，8 位） | 加守护后 | 降低 |
|---|---|---|---:|
| 审讯室男子的皮肤（发橙） | 10.4 | 1.9 | 82% |
| Jesse 的红发 | 18.2 | 10.2 | 44% |

编辑的亮度部分只变化 0.004–0.009 档：光影和质感完整保留，只是不再改肤色。

在编辑域做，而不是在最终画面上做：把编辑分成亮度分量和色度分量（`e − mean(e)`）。在肤色区和原片高饱和区域，限制色度分量的幅度和色相旋转。网络照样可以改光影和质感，但改不了肤色和发色。这正好修掉宣传片里拍到的"肤色发橙、红发变暗"。成本是一个全屏计算着色器，0.1 ms 级。

### ⑦ 恒定成本调度器（壁垒四）

- 每个阶段打 GPU 时间戳，读回延迟 3–4 帧。
- **慢旋钮**：NETS 档位（33% / 35% / 50% / 67% / 100%）。改档要重建 NR feature、清历史，所以带秒级滞回，只在持续超预算或持续富余时切换。
- **快旋钮**：焦点窗口开关（跳过槽 B 的求值立即省下这部分，恢复时软淡入）。
- **运动自适应**：快速转镜头时可以暂时关窗口（运动模糊掩盖细节），静止时开。
- **异步队列**（可选）：NGX 支持在计算队列上求值（Skynizz 已验证），NETS 的小而恒定的负载适合和游戏下一帧重叠。
- 前置超分 / 后置两个插入点都支持，按游戏档案选择。

### 应用层：只选目标帧率

- **初始方案**：按显卡型号查成本表（ms / 百万像素），结合输出分辨率和目标帧率，解出 NETS 档位和是否开焦点窗口。
- **闭环**：Core 每局把实测（每阶段 ms、档位停留时间、帧时间分布）写到统计文件，应用下次启动读回来修正这台机器、这个游戏的成本模型。
- 用户界面上只剩"目标帧率"和"画风"。

## 成本估算（RTX 5060，1440p，新模型，约 2.3 ms / 百万像素）

| 方案 | 每帧网络像素 | 网络成本 | 加上自身合成 | 帧时间 |
|---|---:|---:|---:|---|
| 整屏每帧（RenoDX 默认） | 3.69 M | 8.5 ms | 约 8.6 ms | 平坦 |
| **NETS 50%**（误差约等于固定网格 71%） | 0.92 M | 2.1 ms | 约 2.6–2.9 ms | 平坦 |
| 固定网格 71%（同等误差的对照） | 1.86 M | 4.3 ms | 约 4.3 ms | 平坦 |
| **NETS 35% + 焦点窗口 960×540** | 0.45 M + 0.52 M | 2.2 ms | 约 2.7–3.0 ms | 平坦 |
| **NETS 35%（流畅档）** | 0.45 M | 1.0 ms | 约 1.5–1.8 ms | 平坦 |

"自身合成"指重投影、累积、校验和合成这几个计算着色器，按 0.5–0.8 ms 估。社区的参照：Skynizz 的编辑缓存在 RTX 4070、1440p 上，不跑模型的帧也要 1.85 ms（多遍校验）；它的 x8 预设在 TLOU 上平均约 0.9 ms，但帧时间 p99 摆动 1.8 ms。所以 Prism 的累积必须做得精简：一遍重投影 + 累积，一遍合成。

全是估算，真实数字以 M2 的实测为准。

## 验证计划

1. **参考模式**（只在 RTX 5090 上用）：同一帧同时跑整屏全分辨率 NR 作为标准答案，实时计算我们每个档位的误差。指标沿用社区已有的四个：效果保留率、静止闪烁、细节比、帧时间 p99 摆动。5090 算力够同时跑参考和近似，这是我们做这件事的独特条件。
2. **帧转储工具**：一键保存原图、标准答案、各档位输出、MV、深度，离线比对。
3. **对比基线**：同一场景（CONTROL 开场审讯室、Jesse 镜头）下对比 RenoDX、Skynizz Performance / x8、Prism 各档位。
4. **弱卡外推**：我们只有 5090，用"每百万像素成本"按比例推算 5060/5070；有条件时找 50 系中低端实机复测。

## 已定决策

1. **Core 自己写**，不分叉 RenoDX，也不依赖 ReShade / OptiScaler。RenoDX 和 neural-upstream 是 MIT，可以参考它们的接口发现（参数名、加载门禁、去重、颜色编码），代码里注明出处；Skynizz 的分支是 GPL，只借鉴公开的设计思路，不复制代码。
2. **工具链**：MinGW-w64 g++ 16（本机已有）+ 系统 `d3dcompiler_47.dll` 运行时编译 HLSL，不需要安装 Visual Studio。
3. **着色器先在核显上验证**：每个计算着色器都有 D3D12 测试程序，在 Intel 核显上跑同一组数据，与 `tools/nets-sim` 的 CPU 参考实现逐像素比对，并计时。只有接通 NGX 的部分需要 RTX 50。
